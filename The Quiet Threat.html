What we studied

A simulated company, attacked on purpose.

CICIDS2017 is a public dataset from the Canadian Institute for Cybersecurity. It records a network of about 25 users while real attacks are launched against it. We loaded Friday's flow records into Splunk, then confirmed what we saw in Wireshark.

Findings

What the traffic showed.

Priority 1

Bot: five hosts taking orders

  • Five Windows machines were infected with the Ares botnet.
  • They called the C2 server at 205.174.165.73 on port 8080, which looks like ordinary web browsing.
  • A burst from 10:00 to 11:00 AM, then a steady 42 flows every 10 minutes. A rate that steady means a timer: beaconing.
  • The same pattern continued until about 5 PM as 966 flows labeled BENIGN.

Defense

What we recommend.

Each recommendation comes from something the data showed us.

Because labels missed 966 flows

Detect by behavior, not labels

Alert on steady outbound check ins to one address, one source hitting many ports, and traffic far above its baseline.

Because the real attackers were hidden

Log firewall address translations

Every outside attack looked like it came from the firewall. Translation logs tie inside traffic back to the true source.

Because C2 ran on port 8080

Restrict outbound ports

Workstations should reach the internet only through approved ports and a proxy, so an unexpected connection is blocked or logged.

Because the flood came through the firewall

Filter a DDoS upstream

Work with the internet provider to drop the attack traffic before it reaches the network, and rate limit new connections on port 80.

Our playbook, phase by phase
01

Preparation

Baseline normal traffic and turn on translation logging.

02

Identification

Behavior based triggers for the bot, the scan, and the flood.

03

Containment

Isolate the five hosts and block the C2 server on every port.

04

Remediation

Remove the Ares agent or reimage, and close unused services.

05

Recovery

Reconnect one host at a time and confirm zero check ins.

06

Lessons learned

Labels are not enough, and the firewall rules stay on.

How we built it

One playbook for a multi stage attack

We started from CERT Societe Generale's IRM 4 for DDoS, which covers a single attack. We extended it with IRM 5 for malicious network behaviour and IRM 7 for Windows malware, then added steps from our own findings.
